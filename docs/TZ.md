# ТЗ: Интерактивная адаптивная презентация для команды продаж Debexpert

## Контекст

Команде продаж Debexpert нужна интерактивная презентация для встреч с клиентами (продавцами долговых портфелей: лендеры, BHPH-дилеры и т.д.). Ключевое требование — персонализация: за пару минут до встречи менеджер отправляет запрос AI-агенту (Claude) через Slack, агент собирает данные по клиенту, актуализирует презентацию, и менеджер показывает её клиенту онлайн.

Решения, принятые с заказчиком:
- **Формат**: веб-приложение (слайды в браузере, полноэкранный режим).
- **Данные о покупателях**: из хранилища данных компании (то, что сейчас питает Power BI) — прямой запрос при генерации или embed Power BI (решить в фазе 2).
- **Цены рынка**: из Google-таблицы, которую ведёт команда.
- **Актуализация**: AI-агент; менеджер пишет Claude в Slack.
- **Язык презентации**: английский. Оформление — фирменный стиль debexpert.com (Inter, синий #2563EB, тёмно-синий #0F172A, красный логотип; база стилей уже есть в `bhph-page/index.html`).

## Архитектура (принцип)

**Статичный фронтенд + персональный JSON-конфиг клиента, «запекаемый» агентом перед встречей.**

Живого бэкенда на этапе показа нет: раз данные всё равно обновляются агентом за минуты до встречи, агент при генерации делает свежий срез (покупатели из хранилища, цены из Google Sheets, профиль клиента из открытых источников + CRM) и сохраняет его в один файл `clients/<slug>.json`. Презентация — статичное SPA, читающее этот JSON по параметру URL: `.../deck/?client=acme-auto`.

Плюсы: нет инфраструктуры/секретов на фронте, мгновенная загрузка на встрече, работает с любым хостингом (включая уже настроенный GitHub Pages), полная воспроизводимость показанного клиенту.

```
Slack (менеджер) ──> Claude-агент ──┬─> исследование клиента (сайт, штат, тип долга)
                                    ├─> запрос к хранилищу: покупатели (типы, штаты)
                                    ├─> Google Sheets: текущие цены
                                    └─> генерирует clients/<slug>.json + git push
                                            │
                        деплой (GitHub Pages / hosting)
                                            │
        менеджер открывает deck/?client=<slug> и показывает клиенту
```

## Структура репозитория

```
deck/
  index.html          # SPA-презентация (или Vite+React — см. «Стек»)
  assets/             # логотип, шрифты, иконки
  clients/
    _template.json    # шаблон конфига с комментариями-схемой
    demo.json         # демо-клиент для отладки и обучения
agent/
  INSTRUCTIONS.md     # промпт/скилл для Claude-агента: как собирать конфиг
  queries/            # SQL/API-запросы к хранилищу (по одному на виджет)
docs/
  ТЗ.md               # этот документ
```

## Слайды (9 шт.)

Каждый слайд — секция SPA; навигация: стрелки/клик/свайп, прогресс-бар, номер слайда, клавиша `F` — полный экран. Слайды 1–2 полностью персональные, остальные — общие шаблоны с персональными данными.

Порядок утверждён заказчиком: цены идут сразу после покупателей в штате, лотирование — после процесса.

### Слайд 1 — Our Understanding of Your Business (персональный)
- Название клиента, логотип (если агент нашёл), город/штат, тип долга.
- 3–5 карточек «что мы о вас знаем»: масштаб бизнеса, тип портфеля, состояние рынка в его сегменте.
- Блок «Challenges we see»: 3–4 гипотезы о проблемах клиента. Источник — **интернет-исследование агентом**: поиск по клиенту (сайт, новости, отзывы, судебные упоминания) + свежая индустриальная аналитика по его сегменту (тренды delinquency, ставки фондирования, регуляторика) → агент формулирует гипотезы, какие проблемы у клиента вероятны; CRM-заметки менеджера дополняют, если есть.
- Данные: `client.profile`, `client.challenges` (+ `client.industryInsights` с источниками) — генерирует агент.

### Слайд 2 — How Debexpert Solves This (полуперсональный)
- Маппинг: каждая проблема со слайда 1 → решение Debexpert (аукцион, 500+ покупателей, 0 комиссии, 14 дней, NDA и т.д.).
- Реализация: библиотека решений (справочник в коде), агент выбирает релевантные пары `challenge → solution`.

### Слайд 3 — Buyer Network Structure (данные из хранилища)
- Интерактивная диаграмма покупателей платформы с группировкой по типам: family offices, фонды, коллекторские агентства, банки и др. (тот же разрез, что в Power BI).
- Donut/bar с числами; клик по группе — краткое описание типа покупателя.
- Данные: `data.buyers.byType` — срез из хранилища на момент генерации (+ timestamp «as of»).

### Слайд 4 — Buyers in Your State (гео-персонализация)
- Карта США (SVG), подсвечен штат клиента; крупная цифра — число активных покупателей, работающих с этим штатом; рядом соседние штаты для контекста.
- Данные: `data.buyers.byState` + `client.state`.

### Слайд 5 — Current Market Pricing (Google Sheets)
- Таблица/бар-чарт текущих цен по типам долгов (¢ на доллар, min–max), сегмент клиента подсвечен.
- Данные: `data.pricing` — агент читает опубликованный CSV Google-таблицы при генерации; в таблице фиксируем структуру колонок (Asset class | Performance | Price low | Price high | Updated).

### Слайд 6 — The Process (статичный)
- Таймлайн 4–5 шагов: NDA & data room → listing → auction → closing → funding, с длительностями (итого ~14 дней).

### Слайд 7 — Portfolio Lotting Strategy (интерактивный)
- Интерактивный конструктор лотирования: менеджер прямо на встрече двигает контролы — разбивка портфеля по статусу (performing / non-performing), возрасту, балансу, географии — и слайд пересчитывает рекомендуемые лоты и ожидаемые диапазоны цен.
- Если агент знает параметры портфеля клиента — предзаполняет; иначе стартует с типового примера сегмента.
- Данные: `client.portfolio` (опционально) + прайс-диапазоны со слайда 5.

### Слайд 8 — Full Transparency During Your Auction
- Что селлер видит на платформе в ходе аукциона: кто поставил ставку, кто скачал файлы портфеля, чат с менеджером прямо в интерфейсе.
- Реализация: стилизованный мокап интерфейса платформы (лента событий «Buyer #171 placed a bid», «Buyer #054 downloaded the data tape», окно чата) — анимированная демонстрация, без реального бэкенда.

### Слайд 9 — What We Expect From You (финальный)
- Перечень ожиданий от селлера на время аукциона: быть на связи, не уезжать/не пропадать, оперативно высылать недостающие данные, отвечать на вопросы покупателей.
- Закрывающий акцент: «…and for all of this we charge you zero commission» — крупный блок $0 seller fees.
- CTA: контакт менеджера (имя/телефон подставляются из `meta.manager`).

## Схема `clients/<slug>.json` (главный контракт проекта)

```json
{
  "meta":   { "generatedAt": "...", "manager": { "name": "...", "phone": "...", "email": "..." } },
  "client": { "name": "...", "state": "TX", "segment": "BHPH", "logoUrl": null,
              "profile": ["..."], "challenges": [{ "title": "...", "detail": "..." }],
              "portfolio": { "faceValue": null, "accounts": null, "performingShare": null } },
  "data":   { "buyers": { "byType": [...], "byState": {...}, "asOf": "..." },
              "pricing": { "rows": [...], "asOf": "..." } },
  "solutions": [{ "challengeRef": 0, "title": "...", "detail": "..." }]
}
```

Все поля данных — со снапшотом и датой; отсутствие поля не ломает слайд (fallback на типовые значения сегмента).

## Шеринг-ссылка с email-гейтом и трекингом просмотров

После встречи менеджер отправляет клиенту **персональную ссылку на его презентацию** (та же ссылка `deck/?client=<slug>`, режим «share»). Поведение:

1. **Email-гейт.** При открытии по шеринг-ссылке контент скрыт; показывается экран в стиле Debexpert: «Enter your email to view the presentation». Без ввода корректного email слайды не открываются и скачивание недоступно. Введённый email запоминается в браузере (localStorage) — повторный вход без формы.
2. **Отбивка в Slack.** При каждом входе (и при повторных открытиях в новой сессии) менеджеру приходит уведомление в Slack: имя дека/клиента, введённый email, время, (опц.) сколько слайдов досмотрели. Формат: сообщение в канал `#deck-views` + упоминание менеджера из `meta.manager`.
3. **Скачивание.** После ввода email доступна кнопка «Download PDF» — экспорт слайдов в PDF (со снапшотом данных на момент генерации). Факт скачивания — отдельная отбивка в Slack.

**Реализация.** Email-гейт — это soft-gate (захват лида и трекинг, не криптографическая защита; стандарт для sales-инструментов типа DocSend). Для отправки в Slack нужен минимальный серверный компонент, т.к. Slack-webhook нельзя класть в клиентский JS:

- **Serverless-endpoint** (Cloudflare Worker, бесплатный тариф): `POST /track` с телом `{ deck, email, event: "view" | "download", progress }` → валидация email → `chat.postMessage` / incoming webhook в Slack → `200 OK`, фронт разблокирует контент.
- Secret'ы Slack живут только в конфиге воркера. Endpoint дополнительно пишет события в KV-хранилище воркера — простая история просмотров на будущее.
- Фронт при недоступности endpoint'а показывает мягкую ошибку и пробует ещё раз (гейт не открывается без успешного ответа).

## AI-агент (Slack → Claude)

- Канал: Claude in Slack (Claude Tag) в рабочем workspace; менеджер пишет: «Prepare deck for Acme Auto Finance, BHPH dealer in Texas, meeting in 30 min. Pain points: слишком долго собирают payments, нужен кэш на закупку машин».
- Агент по `agent/INSTRUCTIONS.md` (скилл): интернет-исследование клиента и индустриальной аналитики его сегмента (гипотезы о проблемах для слайда 1) → тянет срезы (хранилище, Google Sheets) → генерирует `clients/<slug>.json` → коммит+пуш → отвечает в Slack ссылкой `deck/?client=<slug>`.
- Фаза 1 обходится без Slack: тот же сценарий запускается из Claude Code вручную.

**Автономность от локального компьютера.** Вся продакшн-цепочка живёт в облаке и не зависит от включённого компьютера кого-либо из команды: презентация — на GitHub Pages, email-гейт и Slack-отбивки — на Cloudflare Worker, генерация деков — через Claude in Slack (облачные сессии). Локальный компьютер нужен только на этапе разработки. Единственное требование: хранилище данных должно быть доступно облачному агенту (не только из офисной сети) — иначе для срезов покупателей настраиваем регулярный автоэкспорт из хранилища в облако (напр., ежедневный JSON в тот же репозиторий).

## Стек и хостинг

- **Фронтенд**: один самодостаточный `index.html` (vanilla JS + CSS, стиль из `bhph-page`) — без сборки, чтобы агент мог при необходимости править и деплой был тривиален. Графики — лёгкая встроенная SVG-отрисовка (donut, bars, карта США), без внешних CDN.
- **Хостинг**: GitHub Pages в существующем аккаунте (уже настроен и проверен на `nastyapavlin.github.io/test`); отдельный приватный репо + Pages, если нужен доступ по ссылке без индексации. Продакшн-вариант — поддомен `deck.debexpert.com` (CNAME) — решение на фазе 3.
- **Секреты** (доступ к хранилищу, Sheets): только на стороне агента, во фронтенд не попадают.

## Фазы реализации

**Фаза 1 — MVP-каркас (первый деливерабл).**
Презентация из 7 слайдов с демо-данными (`clients/demo.json`), полный дизайн в стиле Debexpert, навигация, интерактив слайдов 3–5, деплой на GitHub Pages. Критерий приёмки: менеджер может показать демо-клиента на встрече.

**Фаза 2 — Данные.**
Google Sheets по ценам (согласовать структуру таблицы, опубликовать CSV); выбрать способ доступа к покупателям: SQL к хранилищу (нужны реквизиты и разрешение) или экспорт из Power BI; оформить `agent/queries/`. Критерий: конфиг собирается из реальных данных одной командой.

**Фаза 3 — Slack-агент.**
`agent/INSTRUCTIONS.md` как скилл; подключение Claude in Slack; сквозной тест «сообщение в Slack → готовая ссылка за ≤5 минут». Настройка постоянного URL.

**Фаза 4 — Шеринг-ссылка и трекинг.**
Email-гейт на фронте, Cloudflare Worker `/track`, Slack-уведомления о просмотрах и скачиваниях, кнопка «Download PDF». Критерий приёмки: клиент открывает ссылку, вводит email, смотрит и скачивает дек — менеджер получает обе отбивки в Slack с этим email.

**Фаза 5 — Полировка (по итогам пилота).**
Версия для шаринга экрана в Zoom, история просмотров (кто/когда/сколько слайдов), аналитика использования.

## Открытые вопросы (не блокируют фазу 1)

1. Что за хранилище (SQL Server / BigQuery / другое) и как агент получит доступ — реквизиты нужны к фазе 2.
2. Power BI embed требует лицензий/настройки — нужен только если захотим живые визуалы вместо снапшотов.
3. Приватность: держать ли деки в публичном GitHub Pages (URL-обфускация) или нужен приватный хостинг — решить до показов реальным клиентам; email-гейт скрывает контент от случайных посетителей, но исходный JSON в публичном репо виден.
4. Ссылка на Google-таблицу с ценами и её структура.
5. Slack-канал для отбивок о просмотрах (`#deck-views` или личные сообщения менеджеру) и доступ к созданию Slack-приложения/webhook.

## Верификация

- Открыть `deck/?client=demo` на десктопе и на проекторе (1920×1080), пройти все 7 слайдов, проверить интерактив лотирования и карту штатов.
- Сломанный/отсутствующий конфиг → внятная заглушка, а не белый экран.
- Сгенерировать тестового клиента по сценарию агента и убедиться, что слайды 1–2 и 4 корректно персонализировались.
- Шеринг-режим: открыть ссылку в приватном окне → контент скрыт до ввода email → после ввода приходит Slack-отбивка с этим email; скачать PDF → вторая отбивка.
